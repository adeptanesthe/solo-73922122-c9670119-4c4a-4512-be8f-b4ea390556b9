# 返修机故障占比估算（FastAPI + NumPy）

备件前估算一批返修机中**电源 / 驱动 / 控制**三类故障各有多少台。
上传含「机器编号 + 分类器初判」的 CSV（≤500 台），维修班组随机拆检、
按台登记/更正/撤回实检类别，系统按实检样本拟合未检件的故障占比，
折算台数后加上各类实检数给出全批估计。

## 一、估算口径

1. 对已拆检机器，按**实检类别**分组，统计每组中各初判类别的经验概率，
   组成 3×3 混淆概率矩阵 `P`（行=实检，列=初判，每行和为 1）。
2. 未检件的初判经验分布为 `q`（各类未检件初判计数 / 未检台数，和为 1）。
3. 在单纯形约束 `π ≥ 0`、`Σπ = 1` 下，用 NumPy 求使平方误差
   `SSE = ‖Pᵀπ − q‖²` 最小的故障占比 `π`。求解器枚举内部点（等式 KKT）、
   三条边（一维解析解）和三个顶点，取 SSE 最小的可行解，矩阵亏秩时
   仍保证有候选返回（见 `app/estimation.py:_solve_simplex`）。
4. 各类估计台数 = 实检台数 + `π_k × 未检台数`（三类折算之和守恒为未检总数）。

### 门控规则

- **仍有未检件**时，若任一故障类别没有实检样本，或混淆矩阵不满秩
  （`numpy.linalg.matrix_rank` < 3），**撤下估数**并在页面提示补检原因。
- **全部拆完**时不做拟合，直接返回各类实检实数。
- 撤回一台后该台立即重新计入未检，门控与估数随之重算。

## 二、拟合复用与并发一致性（本轮优化）

多个拆检窗口每 3 秒轮询时，相同分类统计会反复触发最小二乘求解。
本版在不改变估算口径的前提下做了三层优化与一致性保障：

1. **同批成功拟合缓存**：最小二乘只依赖归一化后的拟合输入 `(P, q)`，
   `fit_input_key` 将其固化为可哈希键。同批最近一次成功拟合的输入若与
   当前快照完全相同，直接复用 `π` 与 `sse`（响应 `fit_source=cache`）；
   实检数、未检折算、机器清单仍按各自请求时的快照单独计算。
2. **相同输入单飞（single-flight）**：同批并发请求遇到相同拟合输入时，
   共享同一个在途任务，求解只执行一次；发起方标记 `solved`，并入方
   标记 `inflight_reuse`，三者返回完全一致的拟合结果。
3. **求解卸载、不持锁**：最小二乘在线程池（4 worker）执行，期间不持有
   异步锁，因此拟合尚未结束时，登记、更正、撤回、换批都可即时生效。

### 快照版本与迟到结果保护

- 每次登记/更正/撤回递增快照 `version`，每次换批递增批次 `generation`
  并清空缓存与在途登记表。
- 服务端在拟合完成后回锁核对当前快照的拟合键：键已变化（或已换批、
  已全检、进入门控）则放弃迟到结果、按新快照重新处理，**迟到拟合永不
  覆盖较新记录**。
- 前端同样按 `version` 丢弃迟到的轮询/在途响应，双保险。
- 换批后旧世代任务的结果不会写回新批次（成功不进缓存、失败不弹错误）。

### 拟合失败处理

- 拟合抛错（数值异常、非有限值等）时撤下估数并返回中文提示
  （`fit_source=failed`、`fit_error`），**已登记实检全部保留**；
  失败不写缓存、在途登记立即摘除，**同一输入可直接重试**。

### 并发与存储

- 拆检记录保存在单进程内存中，所有读写经同一把 `asyncio.Lock` 串行化。
  两个浏览器窗口同时登记/更正/撤回（含同一台机器）时，两笔修改都不丢失，
  接口返回的机器明细、实检数与估数始终来自持锁期间的同一份快照。
- 部署固定 `uvicorn --workers 1`（见 `docker-compose.yml` / `Dockerfile`）；
  多进程/多副本需换成数据库等共享存储。

## 四、启动方式

### Docker Compose（推荐演示）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

### 本地直接运行

```bash
pip install -r requirements.txt
python scripts/generate_sample.py 120 data/sample_machines.csv   # 可选
uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 1
```

页面操作：上传 `data/sample_machines.csv` → 在机器行点击
「电源/驱动/控制」登记或更正 → 「撤回」使该台重算未检；
上方卡片实时显示实检数、未检折算、全批估计、`P`/`q`/`π` 与 SSE、
拟合来源（新求解/缓存复用/在途并入/全检实数/门控/失败）以及补检提示。
**复用占比时，未检折算随实检记录所在快照同步更新。**

### CSV 格式

表头支持 `机器编号,初判` 或 `id,initial`（UTF-8，含 BOM 亦可）；
类别支持中英文：`电源/power`、`驱动/drive`、`控制/control`。
编号不可重复，空行容忍，超过 500 台或类别非法返回 400 及中文原因。

- `pytest`：**27 项全部通过**（原 19 项 + 新增 8 项）。新增项覆盖：
  相同快照缓存复用且 `π/SSE` 逐值相等、并发同输入只求解一次
  （1 `solved` + 2 `inflight_reuse`）、拟合进行中登记即时生效且迟到
  结果不覆盖较新版本、拟合失败提示且实检保留/同输入可重试、撤回后
  按新快照重算并重新求解、换批清空缓存且世代隔离（含旧批次拟合失败
  不污染新批次）、并发复用叠加并发修改计数自洽。
- 真实 uvicorn 服务端到端冒烟 **65 项检查全部 PASS**：上传 120 台 →
  满秩样本估数恢复且台数守恒 → 相同快照轮询命中缓存、未检折算随快照
  一致 → 并发同输入至多求解一次 → 更正后实检数同步并重新求解 →
  撤回重算未检且守恒 → 撤回某类全部样本后门控撤下并提示
  「缺少实检类别样本：控制」→ 补检恢复 → 两线程并发改不同机器两笔均
  生效且明细与计数一致 → 全检返回实数（39/59/22，合计 120）→
  换批后版本归零并重新门控。
- 原有口径测试（求解器与细网格暴力参考解 12 组随机矩阵交叉验证、
  精确还原、边界解、缺类/不满秩门控、全检实数、上传校验与错误路径、
  `asyncio.gather` 并发）全部保持通过，估算口径未变。
- 前端内联脚本通过 `node --check` 语法校验。

## 七、未完成项 / 已知限制

1. **本环境未安装 Docker**，`docker compose up --build` 未在本机实际
   执行；Dockerfile/compose 仅做了 YAML 语法与配置核对（单 worker、
   健康检查保持不变），需在有 Docker 的环境再跑一次确认。
2. 内存存储 + 单 worker：服务重启或重新上传会清空拆检记录；没有用户/
   多批次隔离，同一时刻只保留一个批次。
3. 经验混淆矩阵直接采用样本频率，未做平滑；某类实检样本很少时概率估计
   噪声较大（门控只保证三类齐且满秩，不保证样本量充足）。
4. 估数台数为折算小数（页面保留两位小数），未做取整分配；如需整数备件
   建议，可另加最大余数法取整。
5. 前端轮询间隔固定 3 秒，未用 WebSocket 推送；版本防覆盖只保证不
   回退，推送式实时同步仍需改造。
6. 拟合缓存只保留同批各输入键的最近成功结果、不设容量上限；演示规模
   （≤500 台）下键数量有限，超大批次频繁变更时可再加 LRU 限制。
